# Спецификация: движок сценариев (MVP0)

Детальное описание того, что строится по плану
[../../plans/scenario-engine/README.md](../../plans/scenario-engine/README.md).
План отвечает «что и в каком порядке», спецификация — «как именно», до
уровня типов, экшенов, селекторов и правил. Продуктовые правила —
[../../product/flows/scenario-run.md](../../product/flows/scenario-run.md).

## Цели

- Сотрудник проходит сценарий из бандла как визуальную новеллу с
  ветвлением, шкалами и таймерами, получает отчёт, попытка сохраняется
  в браузере.
- Формат сценария и типы — будущий контракт API; замена источника
  данных не трогает слайс, компоненты и типы.
- Логика прохождения целиком в Redux и покрыта unit-тестами через
  `reducer(state, action)`.

## Не входит

- Сервер, редактор модератора, авторизация, персональные результаты
  между устройствами.
- Мобильная раскладка, пауза, восстановление прерванной попытки.
- Достижения, сравнение с коллегами.
- Печатная анимация текста, озвучка.

## Решения, закрывающие открытые вопросы плана

- Все фиксированные наборы строк — string-enum по правилу из
  [../../requirements/types.md](../../requirements/types.md#правила):
  типы узлов, вердикты, статусы, причины, роли, настроения, коды ошибок,
  варианты пропсов. В JSON и `localStorage` лежат строковые значения enum.
- Ответы наставнику считаются в балл наравне с ситуацией; в отчёте они
  не выделяются отдельным блоком, разница видна по темам.
- «Лучше было бы» показывается для `ok` и `bad`.
- Контент лежит в `.json`, импортируется как `unknown` и проходит
  `validateScenario` при загрузке модуля. Тот же путь пройдёт ответ API.
- Идентификатор попытки и `now` создаются в `prepare` action creator,
  редьюсеры остаются чистыми.
- Подтверждение выхода — `window.confirm`, модального компонента в MVP0
  нет.
- Контекст курса передаётся search-параметром `course` на странице
  сценария.

## Критерии приёмки

1. Все JSON из `src/content/` проходят `validateScenario` без ошибок;
   тест падает при любой ошибке.
2. Редьюсер `scenarioRun` покрыт тестами на каждую строку таблиц из
   [engine.md](engine.md) и [report.md](report.md).
3. Каталог на главной ведёт на `/scenarios/:scenarioId` — сценарий во всё
   окно без `AppLayout`; «Начать» на заставке ведёт на сцену, прохождение до финала сохраняет попытку и открывает
   `/scenarios/:scenarioId/attempts/:attemptId`.
4. Истечение любого таймера и ноль на шкале завершают попытку репликой из
   `outcomes` и статусом `failed`.
5. Отчёт содержит все блоки из [report.md](report.md); рекомендаций не
   больше трёх; отчёт открывается повторно из истории попыток.
6. Курс показывает статус каждого сценария по лучшей попытке.
7. Зелёные `yarn lint`, `yarn format:check`, `yarn test`, `yarn build`;
   docs обновлены по таблице из `AGENTS.md`.
