# План: движок сценариев

После выполнения плана сотрудник открывает сценарий из курса, проходит его
как визуальную новеллу с ветвлением, шкалами и таймерами, получает отчёт
с разбором решений и рекомендациями, а лучшая попытка сохраняется.

Продуктовые правила — [../../product/flows/scenario-run.md](../../product/flows/scenario-run.md).
Здесь — архитектура и порядок работ. Детали до уровня типов, экшенов и
правил — в спецификации [../../specs/scenario-engine/README.md](../../specs/scenario-engine/README.md).

## Принятые решения

- **Формат сценария — плоский граф узлов.** Словарь узлов по `id`,
  переходы по ссылкам, ветки могут сходиться. Ложится в таблицу БД и
  визуальный редактор модератора, легко валидируется. Вложенное дерево и
  текстовый DSL отклонены: первое плохо переезжает в БД, второе требует
  парсер и всё равно редактор.
- **Фазы «наставник» и «ситуация» не являются механизмом.** Это обычные
  узлы графа: адаптивное обучение делается ветвлением у вопроса
  наставника, шкалы включаются на сцене флагом видимости.
- **Движок — Redux-слайс `scenarioRun`.** Состояние попытки живёт только
  в store, компоненты читают его селекторами и двигают экшенами. Редьюсеры
  чистые: время приходит в payload, поэтому таймеры и провалы тестируются
  детерминированно через `reducer(state, action)`.
- **Данные через RTK Query с `queryFn`.** В MVP0 сценарии читаются из
  бандла, попытки из `localStorage`. При появлении сервера меняется тело
  endpoint, типы и компоненты не трогаются. JSON сценария и есть будущий
  контракт API.
- **Персонажи, фоны и темы — реестры в коде.** Сценарий ссылается на них
  по `id`, поэтому JSON не знает про пути к картинкам и переезжает в БД
  без изменений.
- **Отчёт строится из попытки и сценария**, а не из UI-состояния: его
  можно открыть повторно из истории.
- **Пояснения к решениям не показываются во время прохождения**, только
  в отчёте. Реакция «внутри» сценария — задача автора через ветвление.
- **Сценарий идёт во всё окно, без `AppLayout`.** Маршрут `SCENARIO`
  стоит рядом с лейаутом; в HUD есть кнопка «Во весь экран» (Fullscreen
  API по клику, не автоматически). Карточки сценариев живут в лейауте:
  каталог всех сценариев на главной, курсы — на `COURSES` и `COURSE`.
- **Лучшая попытка и прогресс курса — чистые функции**, а не селекторы
  store: попытки живут в кеше RTK Query. Статус сценария в курсе
  считается по всем его попыткам, включая начатые вне курса.
- **Заставка перед стартом** на странице сценария: таймеры стартуют по
  «Начать», перезагрузка открывает заставку и новую попытку.
- **Визуальный стиль — комикс «постер»**: контур, цветные жёсткие тени,
  акценты красный и тёмно-синий, шрифт Unbounded для акцентов. Фоны и
  портреты остаются заглушками до шага 7.2.

## Этапы

| Этап | Результат |
|------|-----------|
| 1. Домен и формат | Типы, реестры, первый сценарий в JSON, валидатор |
| 2. Движок | Слайс `scenarioRun`: редьюсеры, селекторы, тесты |
| 3. Данные | RTK Query endpoints для сценариев, курсов, попыток; хук таймеров |
| 4. Экран сценария | Каталог, заставка, сцена во всё окно, HUD, финал со штампом |
| 5. Отчёт | Пороги, балл, разбор решений, рекомендации |
| 6. Курсы и результаты | Список курсов, курс, лучшая попытка, история |
| 7. Контент и подготовка к серверу | Реальные сценарии, персонажи, контракт API |

Детали — [iterations.md](iterations.md).
