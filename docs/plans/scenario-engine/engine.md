# Механизм обработки сценария

Движок — Redux-слайс `scenarioRun` в `src/store/slices/scenario-run/`.
Состояние попытки живёт **только** в store. Компоненты читают его через
селекторы и двигают через экшены; локального состояния прохождения в
React нет. Редьюсеры чистые: текущее время приходит в payload экшена,
`Date.now()` внутри слайса не вызывается.

## Состояние слайса

| Поле | Содержимое |
|------|------------|
| `scenario` | Снимок сценария на время попытки: редьюсерам нужен граф, а версия фиксируется на старте |
| `status` | `idle`, `running`, `finished` |
| `courseId?` | Откуда открыт сценарий, для «Следующий сценарий» |
| `currentNodeId` | Текущий узел |
| `stage` | Накопленная сцена: фон, слоты, видимость шкал |
| `meters` | Текущие значения шкал по `id` |
| `flags` | Установленные флаги |
| `startedAt`, `scenarioDeadlineAt?`, `nodeDeadlineAt?` | Метки времени, миллисекунды |
| `log` | Журнал решений: узел, вариант, применённые эффекты, значения шкал после, время |
| `ending?` | Как закончилась попытка: вид, реплика, результат |

`ending.kind`: `end` (дошли до финала), `timeout`, `meterDepleted`.
`ending.status`: `passed` или `failed`, по правилам из
[feedback.md](feedback.md).

## Экшены

| Экшен | Кто диспатчит | Что делает редьюсер |
|-------|---------------|---------------------|
| `runStarted({ scenario, courseId?, now })` | заставка, «Начать» | Кладёт снимок сценария, заполняет шкалы `initial`, ставит дедлайн сценария, входит в `startNodeId` |
| `advanced({ now })` | сцена, «Далее» на `line` | Проверяет дедлайны, разрешает `next`, входит в узел |
| `optionChosen({ optionId, now })` | сцена, клик по варианту | Проверяет дедлайны и видимость варианта, применяет эффекты, пишет журнал, проверяет истощение шкал, разрешает `next`, входит в узел |
| `expired({ now })` | хук таймеров | Если дедлайн прошёл, завершает попытку с `timeout`; иначе состояние не меняется |
| `runLeft()` | «Выйти», уход с отчётом | Сбрасывает слайс в `idle` |

`now` подставляют action creators через `prepare`, компоненты его не
передают. Экшены на попытке в `finished` или `idle` состояние не меняют.

Внутренний шаг «вход в узел», общий для трёх редьюсеров:

1. Слить `stage` узла с накопленной сценой.
2. Для `choice` с `timeLimitSec` поставить `nodeDeadlineAt`, иначе снять.
3. Для `end` перевести в `finished`: `ending.kind = end`, результат по
   правилам.

## Порядок проверок в `optionChosen`

1. Дедлайны: любой прошёл → завершение `timeout`, выбор не применяется.
   Это защита от клика, пришедшего позже тика таймера.
2. Вариант существует и его `if` выполняется, иначе ошибка программиста,
   а не сценария: UI не должен был его показать.
3. Эффекты по порядку; шкалы обрезаются по `min` и `max`.
4. Запись в журнал.
5. Любая шкала на `min` → завершение `meterDepleted` с репликой из
   `outcomes.meterDepleted[meter]`. Переход по `next` не выполняется.
6. Разрешение `next`: первое условие, которое выполняется на уже
   обновлённых шкалах и флагах.

## Селекторы

Компоненты не разбирают граф сами: всё производное считают селекторы
слайса, экспортируемые через барель `@/store`.

| Селектор | Возвращает |
|----------|------------|
| `selectRunStatus` | `idle`, `running`, `finished` |
| `selectCurrentNode` | Узел из снимка сценария |
| `selectVisibleOptions` | Варианты текущего `choice` с выполненным `if`, в порядке сценария |
| `selectStage`, `selectMeters` | Для отрисовки сцены и HUD; шкалы вместе с `label`, `min`, `max`, порогом |
| `selectDeadlines` | Дедлайны сценария и узла для хука таймеров |
| `selectEnding` | Финальная реплика и результат |
| `selectAttemptDraft` | Объект `Attempt` из состояния попытки для сохранения |

## Таймеры

- В состоянии хранятся только дедлайны. Остаток считает хук
  `useRunTimers` в контейнере по собственному `now` с интервалом около
  250 мс; это единственное место, где время живёт вне store, и оно
  производное.
- Хук диспатчит `expired`, когда остаток ушёл в ноль. Повторные вызовы
  безопасны.
- Таймер узла заводится при входе в узел и снимается при выходе.
  Возврат в тот же узел заводит его заново.
- Паузы нет. Уход со страницы теряет попытку, поэтому persist слайса не
  нужен.

## Завершение и сохранение

Когда `status` стал `finished`, контейнер показывает `selectEnding`.
По «К отчёту» он берёт `selectAttemptDraft`, вызывает мутацию
`attemptsApi.saveAttempt`, диспатчит `runLeft` и переходит на маршрут
отчёта. Отчёт читает попытку и сценарий из кеша RTK Query, поэтому
слайс попытки ему не нужен.

## Чистые помощники вне слайса

В `src/utils/scenario-engine/` остаются функции, которые не зависят от
состояния попытки и нужны за его пределами:

- `validateScenario` — проверки ниже, в тестах на контент и позже на
  сервере.
- `buildReport` — отчёт из сохранённой попытки и сценария
  ([feedback.md](feedback.md)).
- `compareAttempts` — правило лучшей попытки.

Условия, эффекты и разрешение `next` живут внутри папки слайса как
приватные модули: они часть редьюсеров.

## Реестры

Персонажи, фоны и темы — константы в коде с типизированными `id`.
Редьюсеры к ним не обращаются: они нужны сцене для отрисовки и
валидатору для проверки ссылок. Именно поэтому JSON переедет в БД без
правок.

## Валидация

`validateScenario(scenario, registries)` возвращает список ошибок и
предупреждений. Запускается в unit-тестах на каждый JSON из
`src/content/`; позже те же проверки выполнит редактор модератора и
сервер при сохранении.

Ошибки:

- `startNodeId`, все `next`, `to` указывают на существующие узлы.
- Из стартового узла достижим хотя бы один `end`; каждый узел достижим.
- У `line` есть `next`; у `choice` не меньше двух и не больше четырёх
  вариантов и уникальные `id` вариантов; в списке переходов последний
  без `if`.
- Ссылки на персонажей, фоны, темы, шкалы существуют; персонаж из `stage`
  и `speaker` перечислен в `characters`.
- Есть таймер → есть `outcomes.timeout`; есть шкала → есть
  `outcomes.meterDepleted` для неё.
- `initial` строго больше `min` и не больше `max`; пороги `passCriteria`
  в пределах `min`/`max`.

Предупреждения:

- У `choice` нет ровно одного варианта с `verdict: "best"`.
- Вариант с `review` без `topic`, или тема не входит в `topics` сценария.
- Флаг в `passCriteria` или `if` нигде не устанавливается.

## Размещение в слоях

| Слой | Что |
|------|-----|
| `types/` | `Scenario`, `Course`, `Character`, `Attempt` |
| `constants/` | реестры персонажей, фонов, тем |
| `content/` | JSON сценариев и курсов (новая папка, регистрируется в architecture.md) |
| `store/slices/scenario-run/` | слайс: редьюсеры, приватные условия, эффекты, вход в узел, селекторы |
| `store/apis/` | `scenariosApi`, `coursesApi`, `attemptsApi` на `queryFn` |
| `utils/scenario-engine/` | валидатор, отчёт, сравнение попыток |
| `containers/scenario-player/` | сцена, HUD, хук таймеров |
| `containers/scenario-report/` | отчёт |
