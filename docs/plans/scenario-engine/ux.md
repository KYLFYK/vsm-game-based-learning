# UX прохождения сценария

Ответ на вопросы «как выглядит сценарий» и «что на экране». Десктоп.

## Экраны

| Экран | Маршрут | Назначение |
|-------|---------|------------|
| Карточка сценария | `/scenarios/:scenarioId` | Описание, шкалы, лимит времени, лучший результат, кнопка «Начать» |
| Сцена | тот же маршрут, состояние попытки `running` | Само прохождение |
| Финальная реплика | тот же маршрут, попытка завершена | Последняя реплика роли и кнопка «К отчёту» |
| Отчёт | `/scenarios/:scenarioId/attempts/:attemptId` | Разбор попытки, рекомендации |

Карточка и сцена живут на одной странице: переход «Начать» не меняет URL,
чтобы перезагрузка не оживляла оборванную попытку.

## Раскладка сцены

```
┌─────────────────────────────────────────────────────────────┐
│ Название сценария        [Автор: реплика]     Шкалы  ⏱ 04:12 │  HUD
│                                                             │
│  ┌────────┐                                    ┌────────┐   │
│  │персонаж│ «Реплика персонажа                 │персонаж│   │  сцена
│  │ слева  │  слева»                            │ справа │   │  на фоне
│  └────────┘                                    └────────┘   │
│                                                             │
│              ┌─────────────────────────────┐                │
│              │ 1. Вариант ответа      ⏱ 18 │                │  варианты
│              │ 2. Вариант ответа           │                │
│              │ 3. Вариант ответа           │                │
│              └─────────────────────────────┘                │
└─────────────────────────────────────────────────────────────┘
```

- **Фон** на весь игровой экран, меняется по указанию узла.
- **Слоты персонажей** слева и справа, каждый пуст или занят персонажем с
  настроением. Говорящий подсвечен, второй слегка притушен.
- **Реплика персонажа** в облаке рядом с его слотом, со стороны центра.
- **Реплика автора** сверху по центру, полупрозрачная полоса без
  портрета.
- **Варианты ответа** снизу по центру, 2–4 кнопки с номерами.
- **Кнопка «Далее»** на узле-реплике: клик по сцене, `Enter` или `Space`.

## HUD

| Элемент | Где | Когда виден |
|---------|-----|-------------|
| Название сценария, кнопка «Выйти» | верх слева | всегда |
| Шкалы | верх справа | в сценарии есть шкалы и сцена не скрыла их |
| Таймер сценария | верх справа, рядом со шкалами | у сценария есть лимит |
| Таймер ситуации | внутри блока вариантов | у текущего узла выбора есть лимит |

- Шкала: подпись, полоса, число. Изменение анимируется, рядом на секунду
  всплывает `+10` или `−20`. Порог зачёта, если есть, отмечен риской.
- Таймеры: остаток `мм:сс`; последние 10 секунд подсвечены.
- «Выйти» спрашивает подтверждение: попытка пропадёт.
- Прогресс-бара нет: в нелинейном сценарии он врал бы.

## Поведение

- Реплики и варианты появляются сразу, без печатной анимации: MVP0.
- Клавиатура: `1`–`4` выбирают вариант, `Enter` и `Space` листают.
- Реакция на выбор мгновенная: шкалы и переход к следующему узлу.
- Скрытые условием варианты не отрисовываются; нумерация по видимым.
- Финальная реплика показывается на той же сцене; кнопка «К отчёту»
  сохраняет попытку и переходит на отчёт.
- Досрочный провал (таймаут, шкала на нуле) выглядит так же: реплика
  назначенной роли и «К отчёту».

## Фазы внутри сценария

Наставник, ситуация с пассажиром или их сочетание задаются содержимым
узлов, а не режимами движка:

1. Автор описывает обстановку сверху, на сцене наставник.
2. Наставник объясняет и спрашивает. Верный ответ ведёт дальше, неверный
   в узлы пояснения и обратно к вопросу или к следующему.
3. Сцена меняет фон, выводит пассажира, включает шкалы. Начинается
   ситуация.
4. Финал: реплика наставника или автора, затем отчёт.

Любой шаг можно опустить: сценарий без наставника начинается с шага 3,
сценарий без пассажира заканчивается после шага 2.

## Экран отчёта

Порядок блоков сверху вниз:

1. Итог: «Зачтено» или «Не зачтено» и причина одной фразой.
2. Шкалы: итоговое значение против порога, у каждой график по решениям.
3. Разбор решений по порядку: вопрос, выбранный ответ, оценка, пояснение,
   изменение шкал, «лучше было бы» с текстом лучшего варианта.
4. Темы: где сильно, где слабо.
5. Рекомендации: до трёх сценариев по слабым темам.
6. Действия: «Пройти ещё раз», «К курсу», «Следующий сценарий» (если
   зачтено и есть курс).

Состав данных — [feedback.md](feedback.md).

## Адаптив в будущем

На узком экране остаётся один слот: показывается говорящий персонаж,
сторона и разворот берутся из его исходного слота. Реплика автора и
варианты не меняют место. В формате сценария ничего менять не придётся.
