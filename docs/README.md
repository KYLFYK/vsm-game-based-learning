# Документация

Единая точка входа в документацию проекта. Прежде чем искать ответ в
исходниках — ищи здесь.

> **Принцип:** docs/ отражает текущее состояние кода. Расхождение — баг
> docs/, исправляется в той же задаче, что и код. Правила — в
> [AGENTS.md](../AGENTS.md).

## Как пользоваться

1. **Получил задачу** → начни с этого файла, спустись до раздела.
2. **Нужен файл кода** → карта `src/` в [client/README.md](client/README.md).
3. **Нужен механизм** (маршруты, store, API, стили) → `client/<тема>.md`.
4. **Нужна фича целиком** → [client/features/](client/features/README.md).

## Как поддерживать

- Изменение кода → обновление соответствующего файла docs/ **в той же
  задаче** (таблица в [AGENTS.md](../AGENTS.md#3-главное-правило-docs-синхронны-с-кодом)).
- Файл превысил **200 строк** → разбить и обновить ссылки.
- Имена файлов/типов/API — на английском, пояснения — на русском.
- Новый раздел регистрируется в ближайшем `README.md`.

## Когда обновлять корневой README.md

[README.md](../README.md) — витрина репозитория: что за проект, как
запустить, собрать, где искать остальное. Детали живут здесь, README только
ссылается.

Обновлять README **в той же задаче**, если изменение затрагивает:

| Изменение | Что поправить в README |
|-----------|------------------------|
| Смена стека или версии из таблицы «Стек» | Таблица «Стек» |
| `.env.example`, новая переменная | Раздел «Переменные окружения» |
| Dev-порт, схема запуска | Раздел «Локальная разработка» |
| `docker-compose.yml`, `Dockerfile`, `nginx.conf` | Раздел «Запуск в Docker» |
| npm-скрипт в `package.json` | Раздел «Команды» |
| Требования к Node, Yarn, Docker | Таблица «Требования к окружению» |
| Новый верхнеуровневый раздел docs/ | Таблица «Документация» |
| AI-обвязка (`AGENTS.md`, `.claude/`, `.conductor/`) | Раздел «Работа с ИИ-агентами» + [ai.md](ai.md) |

Чего в README быть не должно: пересказа архитектуры и конвенций, таблиц
env с описанием каждой переменной, описания незакоммиченных планов.
