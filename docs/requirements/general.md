# Общие конвенции

## TypeScript

- TypeScript везде — ни одного `.js` в `src/`.
- `strict` включён. Никаких `any` без объяснения в комментарии рядом;
  правило `typescript/no-explicit-any` — ошибка.
- Импорты типов — через `import type` (`typescript/consistent-type-imports`).
- Импорты между папками `src/` — через алиас `@/`; внутри папки —
  относительные.

## Размер файлов

- Лимит — **300 строк на файл** (`eslint/max-lines` в
  [.oxlintrc.json](../../.oxlintrc.json)).
- Файл вырос — разбей по зонам ответственности в той же задаче: компонент →
  под-компоненты и helpers, хук → несколько хуков.
- Отключать правило точечно нельзя: лимит и есть сигнал к декомпозиции.

## Переменные окружения

- Никаких хардкодов хостов, портов и секретов в коде.
- Код читает env только через `env` из [src/config/env.ts](../../src/config/env.ts);
  `import.meta.env` больше нигде не используется.
- Новая переменная — по порядку:
  1. Поле в `readEnv` ([src/config/read-env.ts](../../src/config/read-env.ts))
     и в моке [src/config/__mocks__/env.ts](../../src/config/__mocks__/env.ts).
  2. Тип в [src/vite-env.d.ts](../../src/vite-env.d.ts).
  3. Значение в [.env.example](../../.env.example).
  4. `ARG`/`ENV` в стадии `builder` [Dockerfile](../../Dockerfile) и
     `build.args` в [docker-compose.yml](../../docker-compose.yml).
  5. Таблица в [../architecture.md](../architecture.md#переменные-окружения).

## Линт и форматирование

- Перед коммитом — `yarn format`, затем `yarn lint`. `--max-warnings 0`:
  любое предупреждение = ошибка.
- Отключение правила комментарием `oxlint-disable-next-line` — только с
  пояснением «почему» после `--`.
- Намеренно неиспользуемые аргументы и переменные — с префиксом `_`.

## Тесты

- Перед завершением задачи — `yarn test` наравне с `yarn lint`. Задача не
  закончена, пока хоть один тест красный.
- **Упавший тест — сигнал разбираться в причине, а не править тест.**
- **Новая логика покрывается unit-тестами в той же задаче**: чистые функции,
  хуки, логика store. Компоненты не тестируются.
- Тест проверяет функционал **самого файла**; зависимости мокаются через
  `jest.mock`.
- Тесты лежат в `__tests__` рядом с тестируемым файлом; имя — имя файла +
  `.spec.ts(x)`. Пример:
  [src/hooks/__tests__/use-document-title.spec.ts](../../src/hooks/__tests__/use-document-title.spec.ts).
- В `describe` — `fn.name`, не строка: `describe(readEnv.name)`.
- Для списков и больших объектов — снапшоты (`toMatchSnapshot`).
- Хуки тестируются через `renderHook` из `@testing-library/react`.

## Комментарии в коде

- Объясняют **почему**, не **что**.
- Только когда поведение неочевидно: ограничение, workaround, инвариант.
- Если убрать комментарий и код останется понятным — не добавляй.
