# Прохождение сценария

## Цель

Сотрудник отрабатывает рабочую ситуацию в форме визуальной новеллы: читает
реплики персонажей, выбирает ответы, видит, как решения меняют лояльность
пассажира и рейтинг безопасности, и в конце получает разбор последствий
принятых решений.

## Роли

- **Сотрудник** — проходит сценарий, смотрит отчёт и историю попыток.
- **Модератор** — в будущем собирает сценарии в редакторе внутри платформы
  и хранит их на сервере. В MVP0 сценарии лежат в коде клиента в JSON,
  формат заранее рассчитан на переезд в базу данных.

## Термины

Сценарий, курс, персонаж, шкала, попытка, тема — таблица терминов в
[../README.md](../README.md#термины).

## Шаги

1. Сотрудник открывает карточку сценария → видит описание, какие шкалы
   участвуют, есть ли лимит времени, свой лучший результат.
2. Нажимает «Начать» → первая сцена, общий таймер сценария (если есть)
   запускается.
3. Читает реплику персонажа или автора → «Далее».
4. Получает вопрос с вариантами → выбирает → шкалы обновляются сразу,
   история идёт по выбранной ветке.
5. Доходит до финальной реплики, либо сценарий обрывается досрочно →
   финальная реплика одной из ролей.
6. Открывается отчёт → может пройти ещё раз, вернуться к курсу или перейти
   к рекомендованному сценарию.

## Состояния и переходы

| Состояние попытки | Кто переводит | Куда |
|-------------------|---------------|------|
| `running` | сотрудник выбирает и листает | `passed`, `failed` |
| `passed` | движок на финале, пороги выполнены | конечное |
| `failed` | движок: таймаут, шкала на нуле, порог не выполнен, финал с принудительным провалом | конечное |

Прерванная попытка (закрыл вкладку, вышел) в MVP0 не сохраняется.

## Ограничения и правила

- Шкалы, таймеры и минимальные пороги — необязательные части сценария.
  Сценарий может быть только диалогом с наставником без шкал, только
  ситуацией с пассажиром, или и тем и другим.
- Шкала на минимуме → немедленный провал: реплика роли, затем отчёт.
- Истёк общий таймер или таймер ситуации → немедленный провал: реплика
  роли, затем отчёт.
- Обратная связь показывается всегда, включая успешное прохождение.
- Попыток сколько угодно. Хранится лучшая: сначала по статусу (`passed`
  выше `failed`), затем по баллу, затем по меньшему времени.
- Курс завершён, когда у каждого его сценария есть попытка `passed`.
- MVP0 рассчитан на десктоп. Адаптив появится позже: на экране один
  персонаж, меняется только сторона и разворот.
